# What each file is, and which tree it was measured on

Regenerated by the scripts in `scripts/perf/`. Kept in the repository
because a number without its plan is an assertion.

| File | Tree | Produced by |
|---|---|---|
| `load-profile.json` | any | `seed-load.mjs` — the corpus every other file was measured against |
| `measure-baseline.json` | 1.81.0-alpha, **before** 0151–0158 | `measure.mjs --tag=baseline` |
| `measure-after.json` | 1.81.0-alpha **+ Track F only** | `measure.mjs --tag=after` |
| `measure-assembled.json` | **wave-16 assembled** (Track F + B, C, D, E, G) | `measure.mjs --tag=assembled` |
| `index-verdicts.json` | wave-16 assembled | `prove-indexes.mjs` |
| `write-cost.json` | wave-16 assembled | `measure-writes.mjs` |
| `cost-model.json` | wave-16 assembled | `cost-model.mjs` |

⚠️ `measure-baseline.json` is the only file a default run does NOT
regenerate — it needs `--tag=baseline` — because it is the "before"
evidence for indexes that are now applied. Once 0151–0154 are in a
database, that state cannot be re-measured without dropping them.

⚠️ The assembled tree here is **five of the six other tracks** (B, C, D,
E, G reconstructed from their delivered zips). Track A's 0129–0132 and
0143–0145 were not available. It reproduces integration's reported
1,442 security tests exactly. See `TRACK-REPORT-WAVE17.md` §1.
